# Адаптивная ассоциация: реализация и проверка на NVIDIA

База: `Sevsese-Branch`, commit `0c3a32e`, YOLO26l 1920 + OSNet x1.0 + baseline memory.
Рабочая ветка: `codex/adaptive-identity-memory`.

На исходном отрезке новый вариант улучшает Global 2D IDF1 с **49,4796% до
51,2772% (+1,7976 п.п.)**. На следующем отрезке: **50,3557% → 50,5990%
(+0,2433 п.п.)**. Во втором случае межкамерный pairwise F1 ухудшается:
**86,9145% → 86,0407%**. Это небольшое улучшение IDF1 на одной сцене,
а не доказательство общего превосходства или нового SOTA.

## Протокол

- NVIDIA PhysicalAI-SmartSpaces, train/Warehouse_000, камеры 3 и 15, 30 FPS.
- Разработка/старый контроль: кадры 0–899, по 900 кадров с каждой камеры.
- Дополнительная проверка: кадры 900–1799, по 900 кадров, новый трекер для
  каждой камеры и отрезка. Новое GPU-распознавание завершилось полностью:
  900 + 900 кадров, 163 локальных трека, примерно 421 секунда.
- 1920, confidence 0.10, ByteTrack, OSNet x1.0 MSMT17, выборка признаков через
  5 кадров. Одинаковые наблюдения и исходные средние embeddings для всех
  вариантов внутри одного отрезка. Геометрия отключена.
- Протокол `global-2d-idf1-v1`, IoU ≥ 0.5, все кадры. Изменена только
  возможность задать начало интервала; формулы и фильтрация GT не менялись.
- Ни matcher, ни память, ни фон, ни refinement не читают GT. Оценщик вызывается
  после экспорта предсказаний. Пороги не подбирались по второму отрезку.
- Последующий отрезок той же train-сцены — временная проверка, а не независимый
  тестовый датасет. Признаки агрегируются offline внутри каждого отрезка.
- Используется GTX 1660 Ti Max-Q. Данные, веса и результаты остаются в `runs/`
  и `data/`, не добавляются в Git.

## Реализованные части плана

| Часть | Реализация и границы |
|---|---|
| Воспроизводимость | `mtmct.benchmark`, фиксированные абляции, проверка числа кадров, диапазона и manifest, SHA256 исходных артефактов и файлов реализации |
| Общие ограничения | `hard_compatible` / `groups_compatible`; проверяется вся группа. Неизмеренный большой разрыв считается неизвестным, измеренный запрет — запретом. Старое окно поиска baseline сохранено для совместимости |
| Время | FPS и явные timestamps трека; offsets применяются и к timestamps, и при сопоставлении проекций; исходные номера кадров сохраняются |
| Галерея | До трёх качественных разнообразных прототипов, средний embedding остаётся опорным; выбросы низкого качества не получают вес за разнообразие |
| Адаптивное связывание | Вклад галереи зависит от надёжности. Неизвестные пространственные/временные признаки не создают штраф. Сначала надёжные связи, затем слабые; неоднозначные совпадения откладываются |
| Граф | Состояния candidate/provisional/confirmed/rejected/revoked, причины решений, top-K кандидаты. Отзыв связи действительно перестраивает компоненты и может разделить identity |
| Память | Режимы legacy/constrained/gallery. JSON-состояние и JSONL-события, стабильные ID и aliases, tentative/confirmed/missing/archived и событие reactivated. Повторное связывание нового пакета со старыми галереями с проверкой историй |
| Разделение треков | Требуются три согласованных признака с каждой стороны смены внешности. Пересчитываются embedding, времена, позиции, samples, UID и соответствие наблюдений. Одиночный плохой crop не вызывает разделение |
| Хронологические признаки | Новые прогоны сохраняют до 256 временных samples на трек. Для старых кэшей признаки заново извлечены из тех же bbox, без повторного детектора и без изменения исходной средней галереи |
| Фон | MOG2 и median_static; слабый коэффициент качества 0.85–1.0, без удаления стоящих людей или генерации детекций из маски. Реальный ablation выполнен с MOG2 |
| Окклюзии | Существующий ремонт использует общую физическую проверку. Исправлен обход отключённой геометрии при восстановлении и подавлении дублей |
| Временные окна | 30-секундное окно кандидатов и отдельная память между пакетами. Перечисление пар пока O(N²), полноценное ускорение длинных записей не заявляется |

Граф реализован на уровне tracklet/identity; наблюдения остаются связанными через
CSV и provenance. Отдельный графовый сервер не нужен. Автоматическое обучение
весов, KPR/pose-модель, повторный ROI-детектор и полноценный иерархический
оптимизатор длинного видео в этот эксперимент не включались. Это следующие
расширения плана, а не скрытые составляющие измеренного прироста.

## Результаты абляций

Окончательные машинные отчёты:

- `runs/adaptive_final_development/summary.csv`, `results.json`, `experiment.json`;
- `runs/adaptive_final_holdout/summary.csv`, `results.json`, `experiment.json`.

`full` = adaptive + gallery memory + sustained split + repair, **без геометрии**.
Память между отрезками намеренно не переносилась в основной таблице: это
обеспечивает одинаковую исходную информацию для контроля и нового алгоритма.
Сохранение/возобновление памяти проверяется отдельно тестами; прирост на длинном
видео для него не заявляется.

| Вариант | IDF1 0-899, % | IDF1 900-1799, % |
|---|---:|---:|
| baseline_memory | 49.4796 | 50.3557 |
| constrained_memory | 49.4796 | 50.3557 |
| gallery_memory | 49.4796 | 50.3557 |
| adaptive | 51.2607 | 49.8401 |
| adaptive_memory | 51.2607 | 50.5961 |
| sustained_split | 49.4796 | 50.3557 |
| repair_memory | 49.4955 | 50.3586 |
| full | 51.2772 | 50.5990 |
| foreground_gallery | 49.4796 | 50.3557 |
| foreground_full | 51.2772 | 50.5951 |

Устойчивых смен личности для автоматического разделения не найдено на обоих
отрезках, в том числе после извлечения хронологических признаков. Поэтому
`sustained_split` воспроизводит контроль. Галерея и общие ограничения в памяти
по отдельности также не изменили результат. Основной эффект даёт адаптивная
ассоциация; на втором отрезке ей необходима память — без памяти IDF1 падает.

Полнота детекций не выросла: **37,1388%** и **40,0000%** на двух отрезках.
Новый алгоритм улучшает назначение ID существующим наблюдениям. Поэтому для
существенного следующего скачка необходимо отдельно работать с пропусками
детектора, а не обещать решить их изменением ассоциации.

Предварительные `adaptive_development`, `adaptive_holdout` и
`adaptive_temporal_*` содержат результаты до исправления обхода выключенной
геометрии. Значения 51,4116% / 50,6261% из них **не являются итоговыми**.
Окончательный вариант не получает скрытой помощи от геометрии.

Ассоциация стала тяжелее по CPU; время каждого запуска сохранено в summary.
Оно включает чтение и проверку кэша; часть абляций выполнялась одновременно,
поэтому это не строгий benchmark скорости. Новый детектор или более тяжёлый
ReID в измеренный вариант не добавлялись.

## Повторение

Из корня репозитория, PowerShell. Новый полный запуск:

```powershell
$env:OPENCV_FFMPEG_THREADS='1'
.venv/Scripts/python.exe -m mtmct --no-download --imgsz 1920 --max-frames 900 --matcher adaptive --memory --memory-mode gallery --split-tracklets --repair-occlusions --evaluate --out runs/adaptive_new
```

Обычный режим по умолчанию не изменён. Для старого контроля используйте
`--matcher baseline --memory` без новых опций.

Повторение основной матрицы из готовых кэшей:

```powershell
.venv/Scripts/python.exe -m mtmct.benchmark --source runs/nvidia_branch_1920 --out runs/adaptive_repeat --gt data/MTMC_Tracking_2026/train/Warehouse_000/ground_truth.json --tracklets runs/nvidia_branch_1920/temporal_tracklets.json --foreground runs/nvidia_branch_1920/foreground_mog2.json
.venv/Scripts/python.exe -m mtmct.benchmark --source runs/nvidia_holdout_1920 --out runs/adaptive_repeat_holdout --start-frame 900 --max-frames 1800 --gt data/MTMC_Tracking_2026/train/Warehouse_000/ground_truth.json --tracklets runs/nvidia_holdout_1920/temporal_tracklets.json --foreground runs/nvidia_holdout_1920/foreground_mog2.json
```

Получение второго кэша с исходными номерами кадров:

```powershell
.venv/Scripts/python.exe -m mtmct.tracking --scene-dir data/MTMC_Tracking_2026/train/Warehouse_000 --out runs/holdout_fresh --reid osnet --imgsz 1920 --conf 0.10 --start-frame 900 --max-frames 1800 --cameras 3 15
```

Для явного сохранения/возобновления межпакетной памяти добавьте к `mtmct.link`
`--memory-state runs/identity_state.json`. Состояние привязано к сцене,
моделям и временной системе; не переносите его между независимыми тестами.

Проверки: `python -m pytest -q`. Покрыты физические запреты и неизвестные
переходы, offsets, некачественные признаки, неоднозначные кандидаты, отзыв
связей, согласованность split, перезапуск памяти и новый local ID, неподвижный
фон, диапазон кадров, запрет скрытого использования геометрии и регрессии
существующего пайплайна. 75 тестов проходят.

Это Global **2D IDF1**, не официальный NVIDIA 3D HOTA. Результаты не доказывают
переносимость на другие сцены или реальные камеры; baseline сохраняется как
контроль, новый режим остаётся явно включаемым.
