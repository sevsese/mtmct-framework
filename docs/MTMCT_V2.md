# MTMCT 2.0

Новый offline-режим использует тот же детектор, локальный трекер и OSNet.
В веб-интерфейсе и офисном CLI выбран MTMCT 2.0. Для сравнения в интерфейсе
есть «Прежний граф», в CLI — `--matcher graph`. Для общей CLI-команды
`python -m mtmct` новый режим включается через `--matcher v2`.

## Что работает

- Глобальное время строится из локального `timestamp_s`, когда оно есть в
  кэше, иначе из FPS камеры и номера кадра. Поддерживаются отдельные
  поправки начала и смещения камеры.
- Для ассоциации офиса используются внешность, время и конфигурация
  переходов. Координаты плана отключены. Расчёт по проверенным координатам
  включается отдельно через `--geometry`; опциональные ковариации читаются
  из `position_covariances`. Без ковариаций используются допуски в метрах.
- Сходство вычисляется из доступных средних векторов, галерей и признаков
  одежды. Прототипы содержат качество, камеру, время и ссылку на кадр.
  Хронологические признаки сохраняются отдельно для диагностики смены ID.
- Вес модальности пропорционален произведению её базового веса, признака
  доступности и надёжности. Сумма до нормировки служит отдельной проверкой
  достаточности свидетельств. Стоимость не интерпретируется как вероятность.
- Надёжные треки формируют компоненты первыми. Слабые треки присоединяются
  по оценкам связей и прототипам, с ограничением вклада каждой камеры.
  Слабые присоединения не пополняют подтверждённую галерею.
- Перед каждым объединением проверяются все межкомпонентные физические
  конфликты. Неизвестный маршрут и длинный разрыв не объявляются физическим
  запретом. Для такого возврата требуется более сильное свидетельство
  внешности. Локальный split требует устойчивого изменения ReID и скачка
  bbox в той же камере. Исходный CSV остаётся нетронутым.
- SQLite хранит ревизии, постоянные ID, прототипы, связи и события merge/split.
  В `association_edges.json` доступны оценки и причины каждого решения.
  Повтор того же прохода не перенумеровывает группы.

Отозвать связь можно командой `python -m mtmct.link --run-dir RUN --matcher v2
--revoke pairs.json`, используя тот же пресет весов, времени и топологии, что
и при исходном запуске. Файл содержит JSON-массив пар `left_uid` и `right_uid`
из журнала. При следующем проходе без файла сохраняются предыдущие отзывы.
Для эксперимента с фоном `mtmct.background` создаёт альтернативный кэш
`--v2-features` для того же набора треков. Маска меняет оценку качества
ограниченно, без удаления детекций или пикселей из входа OSNet.

## Проверка

На NVIDIA Warehouse_000 сравнивались одинаковые наблюдения камер 3 и 15,
геометрия отключена. Настройки выбраны по кадрам 0–899. Кадры 900–1799
использованы для временной проверки на той же сцене.

| Отрезок | Baseline + memory, Global 2D IDF1 | MTMCT 2.0, Global 2D IDF1 |
| --- | ---: | ---: |
| 0–899 | 47.84% | 49.39% |
| 900–1799 | 50.39% | 48.24% |

На проверочном отрезке IDF1 ниже на 2.16 п.п. Опубликованный ранее вариант
`adaptive + gallery memory + split + repair` тоже остаётся сильнее по IDF1
на этих двух отрезках. Новый режим не заменяет старый в общей CLI-команде.

Сравнение воспроизводится через `python -m mtmct.benchmark_v2`. Параметр
`--gallery mean max topk` запускает абляцию, `--start-frame` и `--end-frame`
задают полуоткрытый интервал. Оценщик отдельно сохраняет IDSW, количество ID,
объединений разных GT и фрагментаций. Это диагностический протокол 2D, не
официальный NVIDIA 3D HOTA.

Для офиса сравнение на кэше одной минуты сохраняет 923 наблюдения и 18 локальных
треков. В обоих режимах получается 7 Global ID, 4 из них между камерами.
Разметки личности для оценки точности офиса пока нет.

Для дальнейшего этапа нужны независимые размеченные пары для калибровки
вероятности и официальный протокол нужного датасета для HOTA/DetA/AssA.
Память пока используется для одного offline-прохода и стабильных ревизий той
же записи. Пары перечисляются квадратично по числу локальных треков.
