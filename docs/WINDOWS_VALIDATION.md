# Проверка на Windows, 2026-11-05

Исходный коммит: `7cce486`, ветка проверки: `codex/windows-baseline-validation`.
Windows, Python 3.11.9, NVIDIA GTX 1660 Ti with Max-Q Design (6 GiB),
16 GiB RAM. PyTorch 2.6.0+cu124, torchvision 0.21.0+cu124,
Ultralytics 8.4.0, NumPy 1.26.4, OpenCV 4.11.0.86.
CUDA успешно проверена реальным умножением матриц.

## Установка и запуск

Сначала выполните создание `.venv` и установку из README. Все команды ниже
выполняются из корня проекта в PowerShell. Для сборки Torchreid на этой машине
использовались установленные Visual Studio 2022 C++ Build Tools.

```powershell
git clone https://github.com/KaiyangZhou/deep-person-reid.git .venv/torchreid-source
git -C .venv/torchreid-source checkout f8cd150fdf77e8d9e1ed143b7f308c2c609ded50
.venv/Scripts/python.exe -m pip install -c constraints-windows.txt -r .venv/torchreid-source/requirements.txt wheel lap
.venv/Scripts/python.exe -m pip install --no-build-isolation --no-deps .venv/torchreid-source
.venv/Scripts/python.exe -m pip check
.venv/Scripts/python.exe -m mtmct.gpu_check
.venv/Scripts/python.exe -m mtmct.download --cameras 3 15 --ground-truth
$env:OPENCV_FFMPEG_THREADS='1'
.venv/Scripts/python.exe -m mtmct --no-download --out runs/validated_900
.venv/Scripts/python.exe -m mtmct.evaluate --pred runs/validated_900/global_tracks_2d.csv --gt data/MTMC_Tracking_2026/train/Warehouse_000/ground_truth.json --cameras 3 15 --max-frames 900 --stride 1
```

Torchreid установлен из официального исходного кода, включая Cython-модуль.
Пакеты устанавливать последовательно. `constraints-windows.txt` фиксирует
основные версии проверенного окружения; это не универсальные ограничения
для всех GPU. Полный локальный список пакетов — `runs/environment-freeze.txt`.
CUDA-пара соответствует [официальной таблице PyTorch](https://pytorch.org/get-started/previous-versions/).

## Наблюдения и исправления

Первый запуск завершился неудачно: камера 3 обработана полностью (900 кадров,
59.61 с), камера 15 — только 287 кадров. OpenCV сообщил о нехватке памяти;
старый код считал ошибку чтения нормальным EOF и сохранял неполные треки.
Затем не удалось открыть видео для мозаики. Эти данные остались в
`runs/warehouse_000_cam3_15`, лог — `runs/baseline.log`; это НЕ результат
оценки на 900 кадрах обеих камер.

Исправления:

- Преждевременный EOF теперь вызывает ошибку с номером кадра вместо
  незаметного сохранения неполного результата. Неизвестная длина видео
  по-прежнему допускает обычное завершение чтения.
- Между камерами собираются циклические ссылки YOLO; ресурсы видеозаписи
  освобождаются и при исключениях.
- `run_demo.cmd` использует `.venv`, передаёт аргументы и ограничивает
  декодирование одним потоком по умолчанию. Переменная окружения позволяет
  переопределить число потоков. Повторный запуск сохраняет исходные модели,
  разрешение 960 и параметры алгоритма.
- Итоговая строка корректно называет число рёбер кандидатами, а не принятыми
  связями. Форматы треков и алгоритм глобального сопоставления не менялись.
- Добавлены ограничения версий и полная инструкция установки OSNet;
  генерируемый `*.egg-info` исключён из Git.
- Оценщик сначала максимизирует число пар, проходящих порог IoU, затем
  суммарный IoU. Ранее оптимизация сырого IoU с последующим отбрасыванием
  могла засчитать одну пару вместо двух допустимых. Регрессионный тест
  воспроизводит проблему (recall 0.5 до, 1.0 после). На полном прогоне
  метрики до и после этого исправления совпали.

## Сравнение с README

Проверка train GT на первых 900 кадрах воспроизвела 36 человек в камере 3,
33 в камере 15, 33 общих ID. На первых 100 кадрах проверка геометрии дала
медианные ошибки 0.19 м (камера 3, 455 образцов) и 0.13 м (камера 15,
443 образца), как в README. Это проверка калибровки по GT, не точность
предсказанных детектором координат.

Геометрия остальных камер неоднородна: у камеры 11 медиана 4.85 м,
у камеры 5 p90 14.62 м. Включать пространственные ограничения для всей
сцены без отдельной проверки нельзя.

В исходном Git нет сохранённых predictions, конфигурации окружения старого
эксперимента и реализации Pairwise F1. Поэтому числа 0.3569/0.3759 IDF1
можно сравнивать с новым прогоном, но побитовое воспроизведение и проверка
заявленного Pairwise F1 0.8000 по материалам репозитория невозможны.
Диагностическая 2D IDF1 не заменяет официальный конкурсный 3D HOTA.

## Результат полного прогона

`runs/validated_900`: YOLO26l + ByteTrack + OSNet x1.0 MSMT17,
камеры 3/15, по 900 кадров, imgsz=960, conf=0.10, sample-every=5,
min-similarity=0.80, max-cost=0.125, geometry выключена.
62 локальных трека, 38 Global ID, 15 Global ID связывают обе камеры;
37 рёбер-кандидатов. Мозаика содержит 900 кадров, 30 FPS, 1728×486;
прочитан и визуально проверен кадр 450.

|---|---:|---:|
| Диагностическая IDF1 | 0.3759 | 0.3838 |
| Detection precision | не указан | 0.9840 |
| Detection recall | не указан | 0.2768 |
| Detection F1 | не указан | 0.4320 |
| Камера 3: кадров / время / FPS | не указано | 900 / 61.03 с / 14.75 |

| Пик CUDA tensor memory, камеры 3/15 | не указан | 0.31 / 0.34 GiB |

Время включает локальный tracking/ReID, не скачивание, linking и рендер.
Память отражает только аллокации тензоров PyTorch, не всю память GPU или RAM.
Обработаны 1800 кадров за 123.04 с: около 14.63 кадров/с суммарно при
последовательной обработке. Это офлайн baseline, не 30 FPS двух камер.

Оценка: 29019 GT-боксов, 8163 предсказания, IDTP=7136, IDFP=1027,
IDFN=21883. Разница с README +0.0079 (+0.79 процентного пункта) не доказывает
улучшение алгоритма: прежнее окружение и артефакты неизвестны, а нейросетевой
алгоритм и настройки сохранены. Большая часть потерь связана с пропусками
детекции/локального трекинга; настройкой только глобального сопоставления
их устранить нельзя. Следующая содержательная проверка — recall по размеру
бокса и перекрытиям, затем detector/tracker на отдельном validation-наборе.

Повторное сопоставление без нового нейросетевого инференса:

Настройки по умолчанию оставлены. Эти три измерения на одном train-фрагменте
