После последнего изменения адаптера повторно прошли все 81 Python-тест и три
браузерных сценария без повторения дорогого GPU-инференса. UI-код инференса
и worker после успешного GPU-теста не менялись.

Backend-тесты проверяют импорт собственного формата, единственный Global ID для
двух камер, пагинацию, фильтры, карточки треков, отсутствующие метаданные, повреждённый
CSV/JSON, несовпадение mapping, границы путей, повторяющиеся Camera ID, план помещения,
HTTP Range и реальные bbox из сохранённого результата. Отдельно проверяется набор,
в котором есть только global_ids.json: треки доступны, число наблюдений неизвестно.

Браузерные сценарии проверяют страницы обзора/камер/треков/аналитики/настроек/плана/
загрузки, декодирование двух камер, реальные нарисованные рамки, общее воспроизведение
и паузу (разница времён менее 0.2 с), отключение рамок, поиск ID, открытие карточки и
видео, загрузку CSV и объяснение недоступности backend. Искусственный CSV из теста
подписан `DEMO — UI upload test` и не используется как результат алгоритма.

## Что эти проверки означают

Проверена работоспособность интерфейса и интеграции с существующим алгоритмом.
**Это не новый benchmark точности и не доказательство её прироста.** Для UI не
выполнялся повторный полный инференс 900 кадров: готовый полный результат открывался
из файлов. Короткий прогон нужен для проверки реального пути обработки.

Числа IDF1/IDP/IDR/recall/Pairwise F1 на скриншоте читаются из существующего
metrics.json. Протокол `global-2d-idf1-v1` подписан как пользовательский, не официальный
NVIDIA 3D HOTA. Изменение интерфейса не является улучшением MTMCT-алгоритма.

Визуально проверены скриншоты обзора, камер, таблицы треков и аналитики при ширине
1366 и 1920 px. Длинные таблицы/страницы прокручиваются. Проверки Linux, длительной
многочасовой работы и большого количества одновременно декодируемых камер не выполнялись.
Остальные ограничения перечислены в [WEB_INTERFACE.md](WEB_INTERFACE.md).
